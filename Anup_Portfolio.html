Subscription Features

  • Auto-renew (ISP-level + subscriber-level)
  • Advance renewal — queue next pack before expiry
  • Future activation — set future start date
  • Upgrade — move to higher duration/price pack
  • Renew intent — subscriber-initiated signal
  • Multiple plans — dual slot (plan 1 + plan 2)
  • Switch plan — immediate replacement
  • Pause / Resume — temp suspension

Onboarding Flow

  • Sales captures ISP details & plan requirements
  • CFO + CRO approval gate before onboarding
  • ISP created on CMS; plans mapped under ISP
  • Ops syncs ISP to Bundlr, creates username, dispatches first password via email
  • Ops creates first operator account; credentials sent to ISP email
  • ISP recharges wallet, sets operator prices, assigns packs
  • Operator sets subscriber prices, onboards users
  • Activation: operator wallet hit → ISP wallet deducted (OTTplay revenue)

Distributor Channel

  • Electronics distributors + retailers sell via coupon codes
  • Distributor recharges wallet → generates codes
  • Distributor assigns codes to retailers
  • Commission on activation AND renewal events

Three-Track Search Strategy

  • Track 1 — Exact & Phrase: exact titles, sports teams, synonyms. Sorted by recency + relevance.
  • Track 2 — Prefix & Near-Phrase: short queries use prefix autocomplete; long queries allow slight word variation. Sorted by rating × recency.
  • Track 3 — Fuzzy: misspelling and phonetic fallback. "bhaubali" → "Baahubali". Safety net for zero results.
  • All 3 tracks sent as single Elasticsearch _msearch request — one network round trip.

Pipeline Layers

  • NLP intent parsing — entity + attribute extraction
  • Fuzzy + phonetic matching for Indian transliterations
  • Automated synonym libraries — S2 = Season 2 = Part 2
  • Content filters — premium, parental, maturity, provider
  • Sports widgets + tournament cards (conditional)
  • Merge, de-duplicate, rank — final ordered response

Architecture

  • Client → Node API (/universal_autocomplete/) → Python service (/search/search-suggestions) → Elasticsearch
  • 14 context parameters per request — platform, premium status, parental, maturity, provider filters
"Search is not a feature — it's a signal. Every zero-result is a user telling you what they want that you're not giving them."

Create Subscriber
POST /subscriber/action  ·  mode: "CREATE"

Creates a new subscriber profile without associating any plan. Useful for registering users in the system before activating a service plan — common in CRM integrations where subscriber creation and plan assignment are separate workflows.
