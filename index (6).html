PLATFORM — BUNDLR

A B2B subscription platform built to onboard partners in hours, not weeks

HT Media's B2B subscription business ran on fragmented, partly-manual onboarding across ISPs, banks, and electronics brands. I own the platform's full roadmap — multi-tenant RBAC, a two-wallet margin model between ISPs and operators, and a subscriber retention engine — sole product owner from prioritization through spec.

₹250 Cr cumulative platform revenue, 2M+ subscribers
Renewal ~60% → 85% / 80%
2,500+ partners
99.5% gateway uptime
The trade-off worth knowing about

One large ISP partner's internal security policy blocked external vendor API integration entirely, so we had to reverse the usual flow — Bundlr consuming the partner's APIs instead of the other way round. Staging tests surfaced a real architecture risk: our nightly batch-scheduler assumed activation data was known in advance; this partner's model sent it in real time. Rather than patch around it, I had engineering scope their own timeline and build a generalized real-time processing path — now serving roughly 350,000 users on that integration.

How the subscriber API is designed

The entire subscriber lifecycle — create, activate, renew, switch, upgrade, pause — routes through a single action endpoint with a mode parameter selecting the transition, instead of a REST resource per operation. For partners integrating from very different internal systems, that collapses the integration surface to one contract instead of a dozen. Activation is idempotent and state-aware: the same call creates-and-activates a new subscriber, activates an existing one with no plan, or queues an advance renewal for one who already has an active plan — three outcomes, one endpoint, no branching logic the partner has to own. Subscribers can hold two concurrent plans via independent plan slots, so a base plan and an add-on don't need separate records. Subscriber-initiated renewal and auto-renewal changes land in an approval queue rather than applying directly, giving the ISP a control point without slowing the common case. And failures are typed by exactly which wallet in the ISP/Operator/Super-ISP hierarchy is short, or which side hasn't set a rate — precise enough that an integration can auto-handle predictable failures instead of surfacing a raw error to a human every time.

SEARCH & DISCOVERY — OTTPLAY

A hybrid search and personalization engine for a live streaming platform

Over 60% of searches returned nothing, and recommendations converted to plays only 18% of the time. I designed a dual-engine retrieval system — Elasticsearch for lexical matching, MongoDB Atlas Vector Search for semantic — merged through hybrid ranking, alongside a real-time personalization layer.

Search success 31% → 76%
Zero-result 60% → <5%
Recommend-to-play 18% → 50%
The trade-off worth knowing about

Before this, I'd separately shipped an AI conversational discovery feature that lifted engagement 30% — a good demo, but click-through never justified running two independent discovery surfaces. I made the call to shut it down and fold its intent-matching into the unified hybrid search engine instead of letting a good demo become permanent tech debt.

GENERATIVE PIPELINE — SLURRP MICROSITE BUILDER

A dual-agent AI system that turns a campaign brief into a shippable microsite

Manually, a partner campaign microsite took 22–30 days across designers, developers, and QA. I designed and built the Slurrp Microsite Builder, an AI pipeline with a Maker-Checker review loop, plus automated metadata tagging with confidence-threshold routing for content ops.

Build cycle 22–30d → 3–6d
GTM 6wk/9 teams → 4wk/5 teams
Metadata 72h → <15min, 35+ feeds
The trade-off worth knowing about

I chose a hybrid template-library-plus-LLM architecture over a pure generative approach — a curated library of 50+ QA'd sections handles the predictable majority of requests, and the LLM only fills genuine gaps. It's a less flashy demo than "AI writes the whole page," but it's the difference between 90%+ brand-styling acceptance and a tool nobody trusts enough to skip reviewing.
